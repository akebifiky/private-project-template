# システム要求について

システム要求は、システムデザインを定義するための源泉となるドキュメント群です。
これらの要求は、システムが満たすべき機能的・非機能的な要件を明確にし、設計や実装の指針を提供することを目的としています。

## 運用ルール

- 要求はドメイン (データソースやコンポーネントの単位) ごとに 1 ファイルへ分割し、肥大化を避ける
- 各要求は [EARS (Easy Approach to Requirements Syntax) ](https://alistairmavin.com/ears/) 書式で記述する (種別・書式の詳細は後述の「EARS の種別・書式」を参照)
- 要求 ID は `REQ-<ドメイン略称>-XXX` (3 桁ゼロ埋め、ドメイン内連番) の形式とする (例: `REQ-SOME-DOMAIN-001`)
- 要求は「なぜ (Why) 」その振る舞い・制約が必要かを定義するものとし、 S3 格納パスや Lambda 関数名、使用ライブラリなど「どのように (How) 」実現するかの詳細はシステムデザイン側のドキュメントに委ねる
- 未決定の論点がある要求には、関連する GitLab Issue へのリンクを補足として明記する

## EARS の種別・書式

要求文は [EARS (Easy Approach to Requirements Syntax) ](https://alistairmavin.com/ears/) の記法に従って記述します。 EARS では、要求の性質に応じていくつかの定型パターン (種別) が定義されており、 本プロジェクトのシステム要求では次の種別を用います。

| 種別              | 呼称                     | 書式 (テンプレート)                                                                                    | 使用例                                                                                                                                                                                             |
| ----------------- | ------------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ubiquitous        | 普遍要求                 | システムは、 &lt;システムの振る舞い&gt; しなければならない。                                           | 「システムは、 AWS の認証情報をブラウザへ送出してはならない。                                                                                                                                      |
| Event-driven      | イベント駆動要求         | システムは、 &lt;トリガーとなる事象&gt; とき、 &lt;システムの振る舞い&gt; しなければならない。         | 「システムは、 GitLab 上で push または merge request イベントが発生したとき、当該変更をリアルタイムに取り込まなければならない。」                                                                  |
| State-driven      | 状態駆動要求             | システムは、 &lt;特定の状態にある間&gt; 、 &lt;システムの振る舞い&gt; しなければならない。             | 「システムは、 TXT から Markdown への移行期間中、同一対象について TXT と Markdown の双方が存在する場合、 Markdown を優先しなければならない。」                                                     |
| Unwanted behavior | 望まない振る舞いへの要求 | システムは、 &lt;望ましくない事象を検出した&gt; 場合、 &lt;システムの振る舞い&gt; しなければならない。 | 「システムは、依存パッケージのディレクトリ・バージョン管理用ディレクトリ・ロックファイル・ビルド成果物、または一定サイズを超えるファイルを検出した場合、取り込み対象から除外しなければならない。」 |
| Complex           | 複合要求                 | 上記の種別を複数組み合わせた書式                                                                       | 「システムは、通常運用状態にある間、ユーザーが検索クエリを送信したとき、検索結果を返さなければならない。」(状態駆動要求とイベント駆動要求を組み合わせた例)                                         |

なお、 EARS には上記のほかに Optional feature (オプション機能要求) という種別もありますが、現時点でのシステム要求では使用していません。将来、特定の構成でのみ有効な要求が生じた場合に追加を検討してください。
