# ADR-0001 システム仕様に関わる意志決定を ADR として記録する

- Status: Accepted
- Date: 2026-07-10
- Decision Makers: Yoshioka

## Context

本プロジェクトでは Claude Code など AI エージェントを活用して開発を進めることを想定している。

そのため、システムの仕様を AI エージェントも理解できるようドキュメントを残す必要があるが、
ドキュメントを都度更新していく必要があるという運用負荷が生じてしまい、実装コードとドキュメントの乖離を防げないことが考えられる。

一方で一般に言うシステム仕様などが記載された設計書としての「ドキュメント」は、通常は人間が仕様を理解しやすいよう人間によって管理されることを想定している。
対して AI エージェントは、人間が理解可能な形にドキュメントを整備しようとすると、実装作業と同程度のコンテキストを消費することも考えられる。

そこで、システム仕様に関わる重要な意志決定は、ADR として記録することを原則とし、
それによって「今どんな仕様が有効であるか」を最低限のコンテキスト理解で追跡可能にし、 AI エージェントにとってもフレンドリーなドキュメント管理を目指す。

## Decision

システム仕様に関わる重要な意志決定は、ADR として記録することを原則とする。

この決定により、基本的にはそれぞれの成果物は次のような順番で依存関係を持つことを想定する。

```
ADR -> ドキュメント -> 実装
```

### 管理構造

各 ADR は、次のディレクトリ構造で管理されることを想定する。

```
docs/
  dev-docs/
    content/
      adr/
        ADR-0001-<kebab-case-title>.md
        ADR-0002-<kebab-case-title>.md
        ...
```

## Consequences

- システム仕様に関わる重要な意志決定は、ADR として記録されることになる
- ドキュメントは、ADR を参照する形で管理されることになる
- 実装は、ドキュメントを参照する形で管理されることになる
- これにより、システム仕様に関わる重要な意志決定の追跡が容易になる
- AI エージェントにとっても、システム仕様に関わる重要な意志決定を追跡しやすくなる
- 一方で、ADR を管理する運用負荷が生じることになる
- ドキュメントや実装コードは、ADR を参照する形で管理されることになるため、ドキュメントや実装コードの管理において、ADR の管理が前提となることになる
- そのため、ADR の管理が適切に行われない場合、ドキュメントや実装コードの管理において、混乱が生じる可能性がある
