# ADR-0006: スキャフォールディングのテンプレート構成と出し分けの方式を定める

- Status: Accepted
- Date: 2026-10-22
- Decision Makers: Yoshioka

## Context

これまで本リポジトリは、全体をコピーして新しいリポジトリへ適用することでテンプレートとして機能していた。
この運用では「テンプレートを管理するための作業やファイル」を、テンプレートから切り離して管理できない。
そこで、テンプレートをデータとして扱い、 CLI ツールで生成する構成へ変更する ([Issue #18](https://github.com/akebifiky/private-project-template/issues/18)) 。

あわせて、 GitHub/GitLab の違い (コマンド・用語・ファイル) と、 Actions を利用するかローカルで実行するかを、生成時に選択できる必要がある。
採用するテンプレートエンジンは [ADR-0005](./ADR-0005-adopt-eta-as-template-engine.md) で決定している。

## Decision

### ディレクトリ構成

- リポジトリのルートに CLI ツール (`src/`・`package.json` など) を配置する
- テンプレートデータは `templates/<テンプレート名>/` に配置する。現時点では `templates/default/` のみとし、バリアントは必要になった時点で追加する
- 本リポジトリ自身の開発ドキュメント・規約・CI も、テンプレートを適用した構成とする

### ファイルの扱い

- `.eta` 拡張子のファイルはテンプレートエンジンで描画し、拡張子を除いたファイル名で出力する
- それ以外のファイル (画像などを含む) はそのままコピーする。シンボリックリンクとファイルの実行権限は維持する
- 描画はすべて出力より前に行い、失敗した場合は出力先へ何も書き出さない

### テンプレート変数

- 変数は各テンプレートのマニフェスト (`templates/<名前>/scaffold.manifest.json`) で宣言する。宣言には説明・選択肢・既定値を含める
- 値は CLI の対話入力、または `--vars 'project-name=Example, git-service=github'` で指定する。標準入力が端末でない場合や `--no-interactive` 指定時は、既定値のない変数が未指定であればエラーとする
- 現時点の変数は次のとおり

| 変数 | 内容 | 選択肢・既定値 |
| --- | --- | --- |
| `project-name` | プロジェクト名 | 必須 |
| `git-service` | 利用する Git サービス | `github` (既定) / `gitlab` |
| `ci-mode` | CI の実行方式 | `local` (既定) / `actions` |

- 使用言語に応じたコーディング規約の出し分けは、複数値の指定方法を含めて今後の課題とする

### 出し分けの方式

次の 2 つを併用する。

1. **派生変数によるテンプレート内の書き換え**: 選択値から CLI 側で派生変数を算出し、テンプレートへ渡す (例: `it.git.cli` は `gh` / `glab` 、 `it.git.reviewUnit` は `PR` / `MR`) 。コマンドや用語の違いはこの方式で吸収する
2. **マニフェストによるファイル単位の出し分け**: ファイルのパス (glob) と出力条件の組をマニフェストに宣言する。どの規則にも合致しないファイルは常に出力し、合致する規則がある場合はいずれかの条件を満たすときのみ出力する

### CI

- CI の実体は、 Actions の利用有無にかかわらず `tools/ci` のスクリプトに集約する
- `ci-mode` が `actions` の場合のみ、 `main` 向け PR/MR で `tools/ci/bin/check-all.sh` を実行する基本的な定義 (`.github/` または `.gitlab-ci.yml`) を出力する。プロジェクト固有のワークフローはテンプレートに含めない

### 生成物の検証

次の検証を本ツールの CI で行う。

- 単体テスト (変数の解析・マニフェストの検証・描画・出し分け)
- 変数の組み合わせごとの生成結果のスナップショットテスト
- 生成物の検査 (描画されなかったタグ・テンプレート拡張子の残留・JSON の構文・マニフェストで宣言した禁止パターン) 。 `create` コマンドの実行時にも同じ検査を行う

生成物に対する `tools/ci/bin/check-all.sh` の実行 (スモークテスト) は、実行時間が長いため、必要になった時点で `main` 向け PR/MR の CI への追加を検討する。

## Consequences

- テンプレートの管理作業と、配布されるテンプレートの内容を分離できる
- テンプレートの記述は `.eta` ファイルとマニフェストに閉じるため、 GitHub/GitLab の差異は新しい派生変数や規則の追加で拡張できる
- テンプレートファイル (`.eta`) は、拡張子の都合により Biome や Docusaurus などのツールの対象外となり、生成後にのみ検証される
- マニフェストの禁止パターンにより、選択したサービス以外の記述が生成物へ残ることを機械的に検出できる
- スモークテストを行わないため、生成物の Docusaurus ビルドの成否は、本リポジトリ自身のドキュメントのビルドで間接的に確認するにとどまる
