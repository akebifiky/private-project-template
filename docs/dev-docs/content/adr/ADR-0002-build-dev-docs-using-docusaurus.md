# ADR-0002 開発ドキュメントを Docusaurus を用いて構築する

- Status: Accepted
- Date: 2026-07-10
- Decision Makers: Yoshioka

## Context

開発ドキュメントは、プロジェクトの開発に関わる情報を整理し、共有するための重要な資産である。
開発ドキュメントを適切に管理することで、プロジェクトの透明性が向上し、チームメンバー間のコミュニケーションが円滑になることが期待される。
また、開発ドキュメントは、プロジェクトの新規参加者がプロジェクトの全体像を理解するための重要なリソースともなる。

現在、開発ドキュメントの管理方法については明確な方針が定まっていないため、ドキュメントの散逸や情報の陳腐化が懸念される。
そのため、開発ドキュメントを一元的に管理するためのツールを導入することが望ましいと考えられる。

## Decision

開発ドキュメントを Docusaurus を用いて構築することを決定する。
Docusaurus は、Facebook によって開発された静的サイトジェネレーターであり、ドキュメントサイトの構築に特化している。
Docusaurus を用いることで、ドキュメントの構築と管理が容易になり、プロジェクトのドキュメントが一元的に管理されることになる。
また、Docusaurus は Markdown をサポートしているため、ドキュメントの作成が容易であり、チームメンバーがドキュメントの作成に参加しやすくなることも期待される。

### 管理構造

開発ドキュメントは、 `docs/dev-docs` をルートとして、次のディレクトリ構造を基本として管理されることを想定する。

なお、大きく次のような分類でドキュメントを管理する。

- `project-rules`: コーディング規約など、開発フローを定めるプロジェクトルールを管理するディレクトリ
- `adr`: システム仕様に関連する意思決定を示す ADR を管理するディレクトリ
- `requirements`: 機能がなぜ (why) 必要であるかを示す機能要求に関連するドキュメントを管理するディレクトリ
- `system-design`: 要求をもとに、何 (what) をどのように (how) 実装するかを示すシステムデザインに関連するドキュメントを管理するディレクトリ

上記に加えて、各 Markdown を `content` 配下で管理するものとし、次のような基本構造をベースとすることが想定される。

```
docs/
  dev-docs/
    content/
      project-rules/
        ...
      adr/
        ...
      requirements/
        ...
      system-design/
        ...
```

## Consequences

- 開発ドキュメントは Docusaurus を用いて構築されることになる
- ドキュメントの構築と管理が容易になることが期待される
- プロジェクトのドキュメントが一元的に管理されることになる
- ドキュメントの作成が容易になることが期待される
- チームメンバーがドキュメントの作成に参加しやすくなることが期待される
- 一方で、Docusaurus の導入と運用に関する学習コストが生じることになる
- Docusaurus の機能や制約に合わせたドキュメントの構築が必要になることになる
- Docusaurus のメンテナンスやアップデートに伴う影響が生じる可能性があることになる
