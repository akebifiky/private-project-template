# コーディング規約

以下では、 本プロジェクトにおけるコーディングスタイルおよび設計上の基本的なルールについて定めます。  
本ページで扱うのは言語非依存の共通ルールのみであり、各言語固有のルールは以下のページで定めます。

- Python (`pipelines/`, `services/` 配下) : [Python コーディングルール](./coding-styles-python)
- Node.js/TypeScript (`apps/` 配下) : [Node.js/TypeScript コーディングルール](./coding-styles-nodejs)

## 言語共通ルール

### インデント

- インデント幅は言語ごとの標準・使用するフォーマッタの既定値に従うものとし、本ページでは具体的なスペース数は規定しません
  - 各言語の具体的な値は、上記の言語別ページを参照してください

### 命名

- 変数・関数名などは、平易で意味が明快な英単語を用いる
  - 短さよりも明快さを優先する
  - アクロニムとして認知されていない単語を省略して用いない
- 一文字の変数名 (`a`, `b` など) は使用してはならない
- 状態やフラグを表す場合、曖昧な `activeFlag` などは避け、`activity` など明確な語を用いる
  - フィーチャーフラグなど、一般的に広く認知されている語彙は例外とする
- 大文字・小文字の表記法 (`camelCase` / `snake_case` など) やアクロニムの表記方法は、各言語のコミュニティで広く採用されている標準に従うものとし、本ページでは規定しません
  - 各言語の具体的な規則は、上記の言語別ページを参照してください

### メソッド・関数の命名

- メソッド・関数は基本的にオブジェクトの「操作」・「動作」を表すものであるため、命名は **動詞で始める**
  - **副作用を持つ操作**: 動詞ではじめる
    - ✅ `sendMessage()`, `updateName(name)`
    - ❌ `message()`, `name(name)`
  - **プロパティなどの状態を示す値を応答するだけの操作**: 名詞のみでも可
    - ✅ `name()`, `link()`
  - **真偽値を応答するなど、状態を明示する場合**: `is` / `has` / `can` / `should` などで始める
    - ✅ `isActive()`, `hasChild()`
- オブジェクトの属性を参照するためだけの操作は、 Getter (`get{PropertyName}` のように命名された操作) ではなく、属性名そのものをメソッド名とする
  - ✅ `name()`, `link()`
  - ❌ `getName()`, `getLink()`
- アクセスする想定がない属性に対して、とりあえず Getter/Setter を用意することは禁止する

### 変数

- **定数** は `SCREAMING_CASE` (すべて大文字 + アンダースコア) で命名する

### 全般

- 1行あたりの最大文字数は、各言語で使用するフォーマッタの既定値に従うものとし、本ページでは規定しません
- コメントは **日本語** で記述する
- すべてのクラス・関数・メソッドには、その目的・パラメータ・戻り値・仕様などを明記したコメント (Docstring / JSDoc など) を付す
  - 具体的な書式は、上記の言語別ページを参照してください
- コメントの説明文は、そのメソッド・関数が **何を行うか / 何を応答するか** を明確に記述する
  - 値を応答する操作は「〜を応答します。」のように記述する
  - インスタンスを生成して応答する操作 (コンストラクタ等) は「〜を生成して応答します。」のように記述する
  - 副作用のみを持ち値を応答しない操作は「〜を行います。」のように記述する
- ファイルの末尾には **空行を1行** 入れる
- 複雑度の上昇を避けるため、安易な `if-else` 構造の多用は避け、**早期 return** を心がける
- `import` 文 (または相当する読み込み処理) とコード本体の間には **空行を1つ以上** 設ける

### 例外管理

- 例外・エラーは、各言語で定める共通の基底クラスを継承するものとする
- 例外・エラーメッセージは **必ず日本語** で記述し、どのような場面で生起したかを明確に含める
  - 例: 「プラグイン some-plugin で循環参照が確認されました」ではなく、「プラグインの読み込みにおいて、プラグイン some-plugin で循環参照が確認されました」
- 例外・エラーの種別判定の具体的な方式 (型のみで判別するか、固定のエラーコードを併用するか等) は、各言語で必要性が異なるため、本ページでは規定しません
  - 具体的な実装方針は、上記の言語別ページを参照してください

### タイムゾーン

- 日時を扱う処理では、特に指定がない場合 **UTC (+00:00)** で扱う
- 保存・計算・比較などの内部処理は常に UTC を基準とする
